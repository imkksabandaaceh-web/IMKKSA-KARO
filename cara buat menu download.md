# Cara Membuat Menu Download Proposal PDF (Online)

Panduan untuk membuat fitur menu **Download** seperti di project GPIB Banda Aceh
(`welcome-gpib`) di project lain (misal: `imkksa-bandaaceh.site`), dengan template
PDF yang berbeda.

---

## 1. Apa saja isi fitur ini

| Bagian | Peran |
|---|---|
| 2 file PDF (cover + isi) | Template surat. **Cover wajib punya form field** yang diisi otomatis |
| `pdfUtils.ts` | Isi form di cover → gabung dengan halaman isi → flatten → jadi file PDF siap unduh |
| `DownloadProposal.tsx` | UI: form input (nomor surat, pemohon, tujuan) + tabel riwayat + tombol unduh/edit/hapus |
| Tabel `riwayat_download` (Supabase) | Riwayat proposal global + realtime antar perangkat |
| Login admin | Mengunci form input/edit/hapus (pengunjung umum hanya bisa unduh) |
| Dependensi `pdf-lib` + `@pdf-lib/fontkit` | Library pengolah PDF di browser |

Referensi implementasi di project GPIB:
- `src/utils/pdfUtils.ts` — logika generate PDF
- `src/components/DownloadProposal.tsx` — komponen UI menu Download
- `src/App.tsx` — integrasi menu, state, dan query Supabase (bagian `handleAddProposalSupabase`, `handleEditProposalSupabase`, `handleDeleteProposalSupabase`, dan efek lazy saat tab Download dibuka)

---

## 2. Yang harus disiapkan (selain 2 file PDF)

### a. Form field di PDF cover — paling sering luput ⚠️

Di project GPIB nama field-nya:

- `tanggal_surat`
- `nomor_surat`
- `tujuan_surat`

Di PDF project lain namanya **bisa berbeda**. Cara mengecek:

1. Buka PDF cover dengan **Adobe Acrobat** (menu *Prepare Form*) atau **PDFescape** (gratis, online).
2. Lihat nama tiap text field dan catat persisnya.
3. Nama itu yang harus disesuaikan di kode `pdfUtils.ts`.

> Alternatif: biarkan kode debug (sudah ada di `pdfUtils.ts` project GPIB) yang mencetak
> daftar field ke konsol browser saat PDF di-generate — buka konsol (F12) saat klik
> Download, lalu samakan nama field di kode.

### b. Dependensi npm

```bash
npm install pdf-lib @pdf-lib/fontkit
```

### c. Project Supabase aktif

Variabel di file `.env`:

```
VITE_SUPABASE_URL=...
VITE_SUPABASE_ANON_KEY=...
```

### d. Tabel `riwayat_download` di Supabase

Jalankan SQL berikut di **Supabase Dashboard → SQL Editor**:

```sql
create table if not exists public.riwayat_download (
  id bigint generated by default as identity primary key,
  nomor_surat text not null,
  tujuan_surat text not null,
  pemohon text default '',
  tanggal_surat text default '',
  no_urut integer,
  link_download text default '-',
  created_at timestamptz default now()
);

alter table public.riwayat_download enable row level security;

-- Mode sederhana (tahap awal). Untuk produksi, batasi akses tulis ke admin.
create policy "boleh baca" on public.riwayat_download
  for select using (true);

create policy "boleh tulis" on public.riwayat_download
  for insert with check (true);

create policy "boleh ubah" on public.riwayat_download
  for update using (true);

create policy "boleh hapus" on public.riwayat_download
  for delete using (true);
```

> ⚠️ Kebijakan RLS di atas terbuka untuk semua (mode sederhana). Untuk produksi,
> sebaiknya dibatasi ke user yang sudah login.

### e. Sistem login admin

Jika project kedua sudah punya login, pakai itu untuk mengunci form input/edit/hapus
(`isLoggedIn`). Jika belum, buat login sederhana atau minta AI agent membuatkannya.

## 3. Prompt siap tempel

Salin teks di bawah ini ke AI agent (di project kedua), lalu ganti bagian `[...]`
sesuai kondisi project Anda:

```
Di project ini saya ingin membuat fitur menu "Download" untuk generate proposal PDF secara
online, mengikuti pola yang sudah ada di project GPIB Banda Aceh (welcome-gpib). Tolong tiru
pola arsitekturnya:

1. Dua file PDF template saya taruh di folder public/: satu halaman cover yang MEMILIKI form
   field, dan satu file isi/badan surat tanpa form.
   [Sebutkan nama field PDF Anda di sini, contoh: "Nama field di cover PDF saya adalah:
   tgl_surat, no_surat, tujuan_surat" — atau tulis: "saya belum tahu nama field-nya, tolong
   tambahkan kode debug yang mencetak daftar field saat PDF di-generate"]

2. Saat admin login dan mengisi nomor surat, nama pemohon, dan tujuan lalu menekan tombol
   "PROSES & GENERATE PDF": isi form field di cover, gabungkan dengan halaman isi, flatten,
   lalu unduh sebagai file bernama Proposal_<nomor>.pdf.

3. Ada tabel riwayat download global di Supabase (tabel riwayat_download: id, nomor_surat,
   tujuan_surat, pemohon, tanggal_surat, no_urut, link_download, created_at) dengan pencarian,
   edit, hapus, dan update realtime. Form input/edit/hapus HANYA untuk admin yang login;
   pengunjung umum hanya bisa mengunduh dari tabel.

4. Gunakan pdf-lib dan @pdf-lib/fontkit (tambahkan ke dependencies jika belum ada). Variabel
   VITE_SUPABASE_URL dan VITE_SUPABASE_ANON_KEY sudah tersedia di .env.

5. Integrasikan menu "Download" ke navigasi utama. Ikuti konvensi styling project ini.

Saya sudah menyiapkan: [2 file PDF di public/, kredensial Supabase di .env, tabel riwayat_download
sudah dibuat / belum dibuat].
```

---

## 4. Langkah-langkah sederhana

1. **Siapkan 2 PDF** di folder `public/` project kedua (cover ber-form + isi). Catat nama field-nya.
2. **Buka Supabase → SQL Editor** → jalankan SQL di atas (atau bilang di prompt "tabel belum dibuat, buatkan").
3. **Pastikan `.env`** punya `VITE_SUPABASE_URL` dan `VITE_SUPABASE_ANON_KEY`.
4. **Install dependensi**: `npm install pdf-lib @pdf-lib/fontkit`.
5. **Tempel prompt** di atas ke AI agent di project kedua.
6. **Verifikasi**: login sebagai admin → isi form → klik PROSES → cek PDF terunduh & field terisi.
   Jika nama field salah, buka konsol browser (F12) saat klik download — kode debug akan
   mencetak daftar field yang tersedia, lalu tinggal samakan namanya.

---

## 5. Catatan tambahan

- Fitur ini tidak membutuhkan ImageKit — murni `pdf-lib` + Supabase.
- PDF template (cover + isi) hanya diunduh saat generate proposal, jadi tidak
  memperlambat loading awal situs.
- Untuk menghemat bandwidth, tambahkan cache header di `vercel.json` untuk file PDF
  (lihat `vercel.json` project GPIB).
- Jika nanti menu Download dihapus (rencana Oktober), yang perlu dibersihkan:
  `public/COVER.pdf`, `public/ISI.pdf`, `src/utils/pdfUtils.ts`, serta dependensi
  `pdf-lib` dan `@pdf-lib/fontkit`.
